# 登山ルートエディタ

地理院地図上で奥多摩・奥秩父・富士山周辺の登山ルートを編集し、GPX 1.1で書き出すブラウザアプリです。歩行グラフは生成済みで、ブラウザ内のWeb Workerで探索します。背景地図は国土地理院から直接取得します。

## 起動

Node.js 22.22以降を使用します。探索データが同梱されているため、起動時に元のOSMデータを取得する必要はありません。

```text
npm ci
npm run dev
```

表示されたローカルURLをChromeなどで開きます。地図に2点以上置くと自動で区間を探索します。地点はドラッグするか、「地点を移動」を選んで地図上で移動できます。区間を「手描きに切り替え」ると、入力地点を端点とする区間を作り、クリックで頂点を追加できます。頂点のドラッグや削除、取り消し・やり直しに対応します。

地図上部の「探索できる道」をオンにすると、自動探索グラフの道が白い縁取りの赤線で表示されます。道の近くをクリックして追加・挿入すると、その道に吸着した経由地点を置けます。地点の移動も同様です。広い範囲や道が密集した地域では、地図を拡大すると表示できます。

初期の自動吸着は50 mまでです。「始点／終点の吸着候補」では150 m以内の候補を表示します。長い迂回や不通がある場合、始点側に別経路を引ける候補を表示することがあります。経路から入力地点に向かう紫の点線は吸着位置の目印です。表示中の実線と橙の破線をGPXに出力し、接続しない区間は別のトラックセグメントとして保持します。未解決区間がある場合は地点の移動・吸着候補の選択・手描きへの変更で解消してから出力できます。

未解決の区間は、書き出し状況に表示される番号から開けます。「確定済みの区間だけ保存」を選ぶと、未解決箇所でトラックを分割して別ファイルに保存します。ブラウザのダウンロードが見つからない場合は「GPXの内容をコピー」を使えます。左パネル下部の「診断モード」では、アプリの版、区間ごとの探索結果と吸着距離、書き出し状況をコピーできます。座標を含める場合はチェックを入れてください。

## 参考レイヤーとマイ地点

「参考レイヤー」からGPX・KMLを追加すると、コースの線と名前付き地点が地図に重なります。ファイルごとの表示切替、全体表示、地点名・種類・地図範囲での絞り込みに対応します。KMLの軌跡点は初期の「施設・その他」表示から省き、「すべて」または「軌跡点」で表示できます。絞り込んだ地点の一括保存は、対象件数を確認してから実行します。

コースの線があるファイルの「線の設定」で、太さ・色・線種を変更して見比べられます。色見本を押すとブラウザ標準のカラーピッカーが開きます。「元に戻す」で設定を開いたときの見た目に戻せます。「新規レイヤーの初期値にする」を押すと、次回の読み込みでも使う初期値をこのブラウザに保存します。

地点を選ぶと「マイ地点に保存」「経由地点に追加」「GPXにウェイポイントとして含める」を選べます。マイ地点はこのブラウザのIndexedDBに保存されます。参考ファイル自体は開いている間の表示用です。参考の線と地点は自動探索グラフとは独立して扱います。

地図上部の「ウェイポイント追加」を押して、地図をクリックすると任意の地点を登録できます。地点名・種類・メモを入力し「GPXに追加」を押します。「GPXに含める地点」の一覧から、手動追加した地点の名前や位置を編集したり、削除したりできます。次回も使う地点は「マイ地点に保存」を押してください。

地図下部の「標高プロフィール」を開くと、経路が確定した時点で距離・累積上昇・累積下降と標高グラフが表示されます。グラフにカーソルを合わせるかタップすると、対応する位置が地図に表示されます。国土地理院の標高タイル（DEM10B）をブラウザで読み込んで計算するため通信が必要です。標高を取得できなかった箇所はグラフが途切れます。

地点一覧や地図の丸から地点を選ぶと、しずく型のピンが地図の最前面に出ます。「地図で見る」で画面外の地点にも移動できます。

GoogleマイマップのKMLリンクが入ったファイルでは、「リンク先を読み込む」を押すと施設や線を取得します。ブラウザから取得できないときは「KMLを取得」から地物入りのファイルを取得して読み込めます。

## インストールと更新

公開版はChromeやEdgeのメニューからアプリとしてインストールできます。iPhoneではSafariの共有メニューから「ホーム画面に追加」を選びます。初回にファイルの保存が完了すると、編集画面と同梱の探索データは通信なしでも使えます。地理院の背景地図・標高データと外部KMLの読み込みには通信が必要です。

新しいバージョンは起動時・画面に戻ったとき・使用中に確認します。ダウンロードが終わると「新しいバージョンがあります」と表示されます。編集中の場合は必要なGPXを書き出し、「更新する」を押すと新しい画面に切り替わります。

本番用のPWAをローカルで試すには `npm run build` に続けて `npm run preview` を実行します。開発用の `npm run dev` ではサービスワーカーを登録しません。GitHubの `main` に更新をプッシュすると、GitHub ActionsがビルドしてPagesを更新します。

## この段階の範囲

編集中のルートとしてのGPX読み込み・分割とルート全体の自動保存は後続段階です。編集内容はページを閉じる前にGPXとして書き出してください。

経路データは東経138.52〜139.26°、北緯35.25〜36.08°を対象とし、境界に約3 kmの余白を持たせています。同じOSMノードIDを共有する線分を接続し、通行不可・条件付きのアクセス、ゲート、歩行者の進行方向を評価します。経路はOSM収録内容と用途別の重みに依存します。富士山の現地の通行条件は県の情報を確認できます。 [静岡県の富士山登山ルート情報](https://www.pref.shizuoka.jp/machizukuri/dobokujimusho/fujidoboku/1004260/1034564.html)

## 検証

```text
npm test
npm run test:region
npm run build
npm run test:browser
npm run test:pwa
```

ブラウザ確認ではローカルのChromeを使用します。Windowsの既定場所にChromeかEdgeがない場合は、実行ファイルのパスを環境変数 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` に指定します。画面の確認画像は `test-results/` に保存されます。

## 探索グラフの再生成

`data/source.json` に関東・中部のPBFの版、SHA-256、対象範囲、余白を固定しています。元データの `latest` は更新されるため、完全に同じグラフを作るにはハッシュが一致するPBFが必要です。`tools/osm/fetch.py` は配布元から取得したファイルを照合します。

```text
python -m pip install -r tools/osm/requirements.txt
python tools/osm/fetch.py .data
python tools/osm/prepare.py .data/region.json .data/kanto-latest.osm.pbf .data/chubu-latest.osm.pbf
npm run graph -- .data/region.json
npm run check:graph
```

同梱の探索グラフ、そのハッシュと対象範囲は [データマニフェスト](public/graph/manifest.json) を参照してください。形式の詳細と出典は [探索データの仕様](docs/graph-format.md) に記載しています。
